# Language switching (English + Turkish) — plan

Status: **in progress** (approved 2026-10-01). Contracts: CONTRACTS B.11.

## Context

Hearth's UI is hardcoded English: about 380 strings plus about 75 accessibility strings. About a quarter already
live in small copy modules (`api/errors.ts`, `lib/authNotice.ts`, `lib/emptyStates.ts`, `lib/connectionStatus.ts`,
`stores/notice.ts`, `lib/adminUsers.ts`, `stores/typing.ts`, `lib/chatTimeline.ts`).

- Dates use `toLocale*(undefined)`, so they follow the browser, not an app setting.
- Several server error codes fall through to the server's English `message`.
- There is no i18n library, and `<html lang="en">` is hardcoded.

The user wants a **language section**. Their decisions:

- **English (default) + Turkish.**
- **Saved per account**, so it follows the user; before login, use the stored browser choice or the browser language.
- A **small built-in system with no new dependency**: typed dictionaries, a `t()` helper and `Intl`.
- **A picker in Settings and on the login/register pages.**

## Design

### Contracts and data (lead, Wave 0)

- **Database:** `users.locale varchar(5) NOT NULL DEFAULT 'en' CHECK (locale IN ('en','tr'))`, added by a Drizzle migration.
- **Shared schemas** (`packages/shared/src/schemas/{users,auth,common}.ts`):
  - a new `Locale = z.enum(['en','tr'])`;
  - `Me.locale: Locale` (**not** on `PublicUser`, so it is never broadcast);
  - `UpdateMeRequest` becomes `{displayName?, locale?}`, with at least one field required;
  - `RegisterRequest` gains an optional `locale`, so a user who registers in Turkish is stored as `tr`.
- **CONTRACTS.md:**
  - B.1 gets the column; B.2 gets `Me.locale`; rows 2 and 8 of B.4 get the new fields.
  - A new rule: a locale-only PATCH emits no `user:updated`, since the value is private. Other tabs pick it up on the next `/me` or bootstrap.
  - The UI-contract tables and e2e describe the **English** copy, and e2e runs with `en-US`.

### Web i18n core (`apps/web/src/i18n/`)

- **Messages:**
  - `messages/en/<namespace>.ts` are the source of truth, written `as const`. The namespaces are `common`, `auth`, `settings`, `admin`, `chat`, `voice`, `errors` and `a11y`.
  - `messages/tr/<namespace>.ts` must have the **same shape**. It is typed against the English type, so a missing key is a TypeScript error.
  - Per-namespace files let the parallel agents own separate files.
- **`t(key, params?)`:**
  - typed dotted keys;
  - `{name}` interpolation;
  - plurals through `Intl.PluralRules(locale)`, where an entry may be `{ one, other }` chosen by `params.count`;
  - it works in React and in plain modules (typing text, notices, day labels) through a non-hook `t()` that reads the current locale from a small zustand store (`i18n/store.ts`).
- **`<Trans k params components>`:** for sentences that contain markup, such as "Have an invite? `<link>Register</link>`" or "Type `<b>{name}</b>` to confirm". It uses simple tag substitution and never `dangerouslySetInnerHTML`.
- **`i18n/format.ts`** (reused everywhere), built on `Intl` with the app locale:
  - time and full date, replacing the `formatTime`/`formatFull` code in `MessageItem.tsx`;
  - day labels, using `Intl.RelativeTimeFormat` for Today/Yesterday (replacing `lib/chatTimeline.ts` `dayLabel`) and otherwise the full date;
  - invite and reset-code expiry;
  - `formatBytes` through `Intl.NumberFormat`;
  - `compare(a, b)` through `Intl.Collator(locale)`, replacing the bare `localeCompare` in `Sidebar`, `MembersPanel` and `lib/adminUsers.ts`;
  - `upper(s)` through `toLocaleUpperCase(locale)`, replacing the call in `lib/avatar.ts`.
- **Choosing the language:**
  - When logged in, it's `me.locale`.
  - When logged out, the order is: localStorage `hearth:language` (wrapped in try/catch like `lib/notifications.ts`), then `navigator.language` starting with `tr`, then `en`.
  - After login the account's locale wins. Register sends the language currently chosen.
  - Every change sets `document.documentElement.lang`.
- **Server text:**
  - Every `ErrorCode` the UI can show gets a client-side message in `messages/*/errors.ts`, with context overrides at call sites (for example, CONFLICT on a channel form means "name taken").
  - The server's `message` is only the last-resort fallback.
  - `friendlyValidationMessage` returns keys and params, not English strings.
- **Raw enums shown in the UI:** `AdminUsersPage` role and status get label keys.
- **Not translated:** message content, usernames and display names, channel names, emoji, codes and filenames.
- **Notices and page alerts:** they're translated when they're created, so switching language while one is showing doesn't re-translate it. That's acceptable and noted.

### UI

- **Settings:**
  - A new **Language** `<section>`, placed after Notifications.
  - It holds a `<select>` labelled **Language**, with options in each language's own name ("English", "Türkçe").
  - Changing it saves immediately with PATCH `/me`, switches instantly and shows the status "Language updated." (translated).
- **Login, register and reset password:** the same compact **Language** select in the `AuthCard` footer. It writes `hearth:language` and switches instantly.
- **Testids:** new ones are `language-select` and `settings-language-heading`. Every existing label, name and testid stays in English, because e2e runs in `en-US`.

## Execution (tech lead + subagents)

- **Wave 0 (lead):**
  1. Contract edits.
  2. Shared schemas and their tests.
  3. Set Playwright `use.locale: 'en-US'` in `e2e/playwright.config.ts`.
  4. Commit.
- **Wave 1, in parallel in git worktrees** (each starts with `git reset --hard main`):
  - **server:** the migration, `toMe`, PATCH `/me` for `locale` (no broadcast when only the locale changes), register `locale`, and Vitest.
  - **i18n core (web):** `i18n/` (the store, `t`, plural handling, `Trans`, `format.ts`, locale detection and storage, and the `html lang` sync); `messages/{en,tr}/common.ts` plus the empty namespace files; the `format.ts` migrations of the existing date, sort and upper-case sites; unit tests (plural rules, interpolation, `Trans`, detection order, storage wrapper, formatters in `en` and `tr`).
- **Wave 2, in parallel in worktrees, after the core is merged.** Each agent moves its area's strings into its namespace files (`en` and `tr`) and writes the Turkish text using the glossary:
  - **auth, settings and admin pages:** includes the Settings Language section and the `AuthCard` picker.
  - **chat:** `components/chat/*`, `stores/typing.ts`, `lib/chatTimeline.ts`, `lib/emptyStates.ts`, `lib/attachments.ts`, `api/errors.ts`, and the notice and pageAlert copy.
  - **layout and voice:** `AppLayout`, `Sidebar`, `MembersPanel`, `ConnectionStatus`, `Skeleton`, `EmptyState`, `voice/*`, `VoicePanel`, `VoiceChannels`, `VideoStage`, and the a11y strings.
  - **e2e:** a new `e2e/tests/i18n.spec.ts`.
- **Wave 3:**
  - A **reviewer** checks for missed hardcoded strings (grep), key parity, placeholder parity between `en` and `tr`, Turkish consistency with the glossary, a11y strings, and overflow from longer Turkish text.
  - A fix-up agent handles what the reviewer finds.
  - The lead runs acceptance and commits `feat(i18n): English + Turkish with per-account language`.

## Verification

- **Unit tests** (Vitest):
  - Key-parity and placeholder-parity tests between `en` and `tr`.
  - Plural and interpolation tests.
  - Formatter tests (for example `tr` day labels "Bugün"/"Dün", Turkish sorting of İ/ı/ş, and `upper('i')` giving "İ" in `tr`).
  - Detection-order and storage tests (a stubbed localStorage, like `voice/volume.test.ts`).
  - Existing copy tests stay in English.
  - Server: the migration applies; PATCH `/me {locale:'tr'}` updates `Me.locale` without a `user:updated` broadcast; an invalid locale gets 400; register with `locale` stores it; `/me` and bootstrap include it.
- **e2e:**
  - The full suite runs 3× with `locale: 'en-US'` and must stay green, including the unchanged English selectors.
  - The new `i18n.spec.ts` covers four cases:
    1. On the login page, switching to Türkçe translates the labels and sets `html[lang="tr"]`.
    2. After registering in Turkish, the account locale is `tr` (checked through `/api/me`).
    3. Switching in Settings changes the language instantly and survives a reload and a fresh browser context, since it's per account.
    4. Switching back to English restores the English labels.
- **Full stack:** `@smoke` via :8080.
- **Screenshots** in Turkish at 390 px and 1280 px of the login, channel, settings, admin and voice pages: no overflow, and the longer Turkish strings don't wrap badly.
- **Gates:** `pnpm typecheck`, `lint`, `format:check` and `test`.
- **User check:** a native-speaker skim of the Turkish copy by the user, listed as a follow-up.
